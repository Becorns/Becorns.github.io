## 原理

先来看看正常的流程：
一个Person类，实现serialize接口，

```java
public class Person implements Serializable{
    public String name;
    public int age;

    public Person(String name,int age){
        this.name=name;
        this.age=age;
    }
    @Override
    public String toString(){
        return String.format("Person:{name=%s,age=%s}", this.name,this.age);
    }
}
```

一个serialize类，进行序列化，并写入文件：

```java
public class Serialize {
    public static void serialeze(Object obj) throws IOException {
        ObjectOutputStream oos= new ObjectOutputStream(new FileOutputStream("ser.bin"));
        oos.writeObject(obj);
    }

    public static void main(String args[]) throws IOException {
        Person person=new Person("hutao",17);
        System.out.println(person);
        serialeze(person);

    }
}
```

一个Unserialize反序列化类，从文件/数据流中读取，并反序列为对象：

```java
public class Unserialize {
    public static Object Unserialize(String filename) throws IOException, ClassNotFoundException {
        ObjectInputStream ois=new ObjectInputStream(new FileInputStream(filename));
        Object obj=ois.readObject();
        return obj;
    }

    public static void main(String args[]) throws IOException, ClassNotFoundException {
        Person hutao=(Person)Unserialize("ser.bin");
        System.out.println(hutao);

    }
}
```

这个过程(客户端发送节流给服务器)，服务器接收字节流，调用该对象的方法readObject。如果用户重定义这个方法，那么可以向其中写入恶意函数：

```java
private void readObject(java.io.ObjectInputStream s) throws java.io.IOException, ClassNotFoundException {
        s.defaultReadObject();
        Runtime.getRuntime().exec("calc");
    }
```

这种情况需要条件：反序列化入口(readObject)调用恶意函数。当然，开发者不会真让你这样搞。所以基本是以下情况：

* 入口参数中包含可控类，该类有危险方法，在readObject调用
* 入口类参数中包含可控类，该类调用其他有危险方法的类，readObject中调用
* 构造函数/静态代码块等类加载时隐式执行
